# CLAUDE.md

## Обзор проекта

Shimeji — небольшое desktop buddy-приложение на Python и PySide6. Прозрачное Qt-окно показывает анимированного персонажа, который отдыхает, ходит по экрану, реагирует на мышь, падает на доступные поверхности, показывает реплики и воспроизводит дополнительные анимации. Приложение предназначено для Linux и Windows; дополнительные сценарии сборки есть для Arch Linux и Linux AppImage.

Основная логика находится в `shimeji.py` (около 1400 строк). Отдельных модулей приложения, менеджера зависимостей или автоматизированных тестов в репозитории сейчас нет.

## Структура

- `shimeji.py` — приложение, Qt-виджеты, анимационные состояния, обработка ввода, позиционирование на экранах и поиск верхних границ окон X11/Windows.
- `*.png` — кадры персонажа и анимаций; загружаются по именам, заданным в `shimeji.py`.
- `words.txt` — строки для речевого облачка. Файл читается как UTF-8 с BOM, при ошибке — CP1251.
- `assets/fonts/` — шрифт Press Start 2P и его лицензия.
- `packaging/arch/PKGBUILD` — сборка Arch-пакета; `packaging/arch/shimeji` — командная обёртка; `shimeji.desktop` — desktop entry.
- `packaging/linux/build-appimage.sh` и `packaging/linux/shimeji.desktop` — сборка AppImage.
- `README.md` — инструкции проекта и описание поведения.

## Запуск и сборка

Нативный запуск на Arch:

```sh
sudo pacman -S --needed python pyside6
python shimeji.py
```

Диагностический вывод последовательностей ходьбы без открытия GUI:

```sh
python shimeji.py --show-sequence
```

Сборка и установка Arch-пакета из корня проекта:

```sh
sudo pacman -S --needed base-devel pyside6
cd packaging/arch
makepkg -si
```

Сборка AppImage выполняется скриптом `packaging/linux/build-appimage.sh`; он использует Docker/Linux-среду Debian, устанавливает зависимости через apt/pip и загружает appimagetool. Не запускай его без явного запроса, если требуется только исправить runtime-поведение.

## Важные технические детали

- GUI построен на PySide6/Qt Widgets и использует прозрачность, frameless/tool windows, `WindowStaysOnTopHint`, `WindowTransparentForInput` и таймеры Qt.
- Пути ресурсов вычисляются от `Path(__file__).resolve().parent`; при изменении упаковки сохраняй доступность PNG, `words.txt` и шрифта как в исходном запуске, так и из установленного пакета.
- Размеры обычных кадров проверяются при запуске; несовпадение idle/walk/fall-кадров приводит к `ValueError`.
- Основной таймер работает каждые 40 мс; логика движения и анимации опирается на `time.monotonic()`.
- Функция `find_window_landing_y()` использует Win32 API в Windows и Xlib (`libX11`, `DISPLAY`) в Linux. Под Wayland/XWayland она не получает полный список нативных Wayland-поверхностей; не считать X11-поиск окон универсально работающим под Sway.
- `QScreen.availableGeometry()` применяется для границ экранов и размещения персонажа. Следует учитывать отрицательные координаты мониторов, несколько экранов, масштабирование Qt/HiDPI и изменение конфигурации дисплеев.
- Главный персонаж и вспомогательные overlay/bubble — отдельные окна. Композиторы Wayland могут иначе обрабатывать их прозрачность, stacking, ввод и перемещение, чем X11 WM.
- Не добавляй глобальные переменные `QT_QPA_PLATFORM` или принудительный `xcb` как универсальное исправление: сначала выясни, запущено ли приложение в native Wayland или XWayland, и проверь локальные Qt-плагины/драйвер.

## Работа над исправлениями

- Перед изменениями проследи полный переход состояний в `Shimeji`, связанные обработчики мыши/таймеров и координатные преобразования Qt. Старайся сохранять существующую структуру состояний и стиль Python-кода.
- Для проблем Arch/Sway собирай воспроизводимые данные: способ установки (исходник, pacman-пакет или AppImage), команды запуска, `XDG_SESSION_TYPE`, `WAYLAND_DISPLAY`, `DISPLAY`, сообщения терминала и шаги воспроизведения. Не предполагай, что все случаи Sway работают через один backend.
- Изменения визуального поведения проверяй в реальной сессии пользователя, если доступ к GUI/композитору из среды разработки отсутствует.
- Для быстрых проверок: `python -m py_compile shimeji.py` и `python shimeji.py --show-sequence`. Они не заменяют тест запуска GUI и не проверяют рендеринг/ввод в Sway.
- Проверяй `PKGBUILD` согласованно с исходниками и путями установки. Не включай сгенерированные пакеты (`*.pkg.tar.zst`), кэш сборки и временные артефакты в правки без отдельной причины.
- Не добавляй зависимости, тестовый фреймворк или новую архитектуру без необходимости для конкретного исправления.
